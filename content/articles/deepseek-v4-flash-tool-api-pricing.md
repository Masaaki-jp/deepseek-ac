## リード

V4.1-Flash-1017 と Tool API（Search / Fetch / OCR / ASR / TTS）の料金が公開されました。本記事では料金を「モデル」と「ツール」に分解し、**どのリクエストが課金されるか**と**月額の見積もり式**をコードで固定します。あわせて、2026-10-31 16:00 UTC で終了した無料枠の影響を確認します。

## 前提

- 想定読者: DeepSeek API を既に呼んでいる、または Agent にツールを組み込もうとしているエンジニア
- 必要な環境: Python 3.10+、DeepSeek API キー
- 前提知識: トークン課金の基本、HTTP ステータスコードの読み方
- **重要な注記**: 本記事の単価は 2026-10-17〜19 の発表・報道・第三者情報を突き合わせた整理です。情報源によって数値が食い違う箇所があるため、実装前に必ず公式の Pricing / API Guides で**要確認**してください（後述の「確認手順」を参照）

## 本文

### 発表の骨子

2026-10-17 の V4.1-Flash-1017 は「性能と費用のパレート改善」と位置づけられ、ベンチマーク改善と同時に**出力が短く・完了が速く**なったと説明されています。Web / App / API の3経路で同時提供です。

実装者にとって重要なのは次の2点です。

| 項目 | 内容 | 実装への影響 |
|---|---|---|
| API モデル名 | `deepseek-flash` のまま（変更なしと発表） | 既存コードのモデル名書き換えは不要 |
| Harness | 0.2.1-rc.1 系への更新が推奨されている | 固定バージョンなら回帰テストを1本流す |
| Search & Fetch | 全開発者に開放 | 新規にツール課金が発生する |

モデル名が据え置きなので「気づかないうちに課金対象が増える」構造になっています。ここが最初の落とし穴です。

### 料金は「モデル」と「ツール」で別建て

今回の発表で混乱しやすいのは、**モデル単価は据え置き、ツールが別建てで有料化**という点です。

| 対象 | 課金単位 | 単価（公表値・要確認） |
|---|---|---|
| Search | 1,000 リクエスト | $0.75 |
| Fetch | 1,000 リクエスト | $0.75 |
| OCR | 1,000 ページ | $0.225 |
| ASR | 1 時間 | $0.058（期間限定 50%OFF） |
| TTS | 10,000 文字 | $0.225（期間限定 50%OFF） |

ASR / TTS は期間限定の半額表示です。**割引終了後に単価が2倍になる前提**で予算を立てておくと安全です。

モデル側は、ある第三者ルータでは入力 $0.15 / 出力 $0.60（1M トークン）、報道ベースでは出力が非繁忙 $0.59 / 繁忙 $1.19 と紹介されており、**数値が一致していません**。ピーク時間帯の扱いも含めて、公式 Pricing での確認が必須です。

### 課金されるのは「成功した呼び出し」だけ

公式の Search & Fetch ドキュメントでは、課金条件がかなり明確に定義されています。

- HTTP 200 が返る
- かつ、Search は検索結果が非空 / Fetch は本文抽出に成功

失敗レスポンス、空の検索結果、タイムアウトは課金対象外です。

これは裏を返すと、**リトライ設計がそのままコスト設計になる**ということです。「空結果が返るまで最大5回叩く」実装は、成功するまで無料とはいえ、成功した瞬間に課金が立つうえ呼び出し回数そのものが増えます。空結果は「ツール失敗」ではなく「有益なシグナル」として扱い、プロンプト側でクエリを書き換えるほうが安く済みます。

### 無料枠は 2026-10-31 16:00 UTC で終了済み

DeepSeek Harness、Claude Code、Codex の**サーバーサイドツール呼び出し**は、リリース直後は無料でした。この無料措置は 2026-10-31 16:00 UTC（＝北京時間 11-01 00:00）で終了し、課金が始まっています。本記事の公開時点（2026-11-14）では**すでに有料**です。

つまり、こういうケースが発生します。

- IDE 上のエージェント経由で Search を多用していた → 10月は $0、11月から請求が出る
- 自前コードでは `Search` を明示的に呼んでいない → 「自分は使っていない」と思い込む

まず請求ダッシュボードで 11 月のツール利用行の有無を確認してください。行があれば、それは自分のコードではなく**エージェント側のツール呼び出し**が原因です。

### 見積もりをコードで固定する

単価は情報源で揺れるので、**単価をコードに定数として閉じ込め、差異が出たら1か所直す**形にしておきます。

```python
# tool_cost.py
# 単価は 2026-10 時点の公表値を整理したもの。公式 Pricing で要確認。
UNIT_PRICE_USD = {
    "search": 0.75 / 1_000,      # 成功リクエストあたり
    "fetch":  0.75 / 1_000,
    "ocr":    0.225 / 1_000,     # ページ単位
    "asr":    0.058 / 3_600,     # 秒単位に換算（50%OFF 前提）
    "tts":    0.225 / 10_000,    # 文字単位（50%OFF 前提）
}

def estimate_monthly(calls: dict) -> float:
    """calls: {"search": 月間成功回数, "ocr": 月間ページ数, ...}"""
    return sum(UNIT_PRICE_USD[k] * v for k, v in calls.items())

if __name__ == "__main__":
    monthly = {
        "search": 10_000 * 30,   # 1日1万回
        "ocr":    50_000,        # 月5万ページ
        "tts":    1_000_000,     # 月100万文字
    }
    print(f"${estimate_monthly(monthly):,.2f} / month")
```

出力はおおよそ **$259**（Search $225 + OCR $11.25 + TTS $22.5）です。Search が支配的なので、**Search の呼び出し回数を1回減らすほうが、OCR や TTS を削るより効く**と判断できます。

実装側では、成功時だけカウントする薄いラッパーを挟むと、見積もりと実績のズレが縮みます。

```python
import json, time
from pathlib import Path

LOG = Path("tool_usage.jsonl")

def record(tool: str, status: int, ok: bool, units: int = 1) -> None:
    """成功（HTTP 200 かつ ok=True）のみ課金対象として記録する。"""
    billable = status == 200 and ok
    with LOG.open("a", encoding="utf-8") as f:
        f.write(json.dumps({
            "ts": time.strftime("%Y-%m-%dT%H:%M:%SZ", time.gmtime()),
            "tool": tool, "status": status, "billable": billable, "units": units,
        }, ensure_ascii=False) + "\n")
```

このログを月次で `tool` 別に合計すれば、請求額と突き合わせられます。ズレたらまず**単価の改定**か**課金条件の解釈違い**を疑ってください。

### 競合との比較は「ツール込み」で見る

報道では、コーディング1タスクあたり約 $0.2 で、米国の競合モデル（出力 1M トークンあたり $20〜$25 との比較）の10分の1未満という主張が紹介されています。

ただしこれは**モデル推論のみの比較**であり、Search を1タスクあたり数回呼ぶ構成では前提が変わります。1タスク = 推論1回 + Search 3回（$0.00225）なので、単価差が大きい領域では依然としてモデル側が支配的です。逆に、検索を数十回叩くリサーチ系エージェントでは**ツール代が主役**になります。同じ「DeepSeek は安い」でも、ワークロードによって支配項が入れ替わる点は押さえておきたいところです。

## つまずきポイント

| 症状 | 対処 |
|---|---|
| 11月の請求が想定の数倍 | Harness / Claude Code / Codex 経由のツール呼び出しを疑う。まずツール別の利用行を確認 |
| モデル料金が上がったと誤解 | モデル単価は据え置き発表。増分はツール課金の別建て |
| OCR のコストが合わない | リクエスト単位ではなく**ページ単位**で数える |
| ASR のコストが合わない | **時間単位**。秒で数えている実装は3600で割る |
| 検索結果が空でリトライを繰り返す | 空結果は課金対象外だが、成功時にまとめて立つ。クエリ書き換えに切り替える |
| 単価が情報源ごとに違う | 公式 Pricing を正とする。コードは定数1か所に集約し、差分を吸収できる形にする |
| 割引終了後に請求が倍 | ASR / TTS の期間限定 50%OFF の終了日をカレンダー登録 |

## まとめ

- 料金は「モデル（トークン）」と「ツール（リクエスト / ページ / 時間 / 文字）」で別建て。モデル名は `deepseek-flash` のままで、コード変更なしにツール課金だけが増える
- 課金は HTTP 200 かつ結果非空・抽出成功のときのみ。失敗と空結果は無料なので、リトライ回数がそのままコスト設計になる
- Harness / Claude Code / Codex の無料枠は 2026-10-31 16:00 UTC で終了済み。11月の請求を最初に確認する
- 単価は情報源で食い違う箇所がある。定数を1か所に集約し、公式ドキュメントで要確認する運用にする
- 支配項はワークロードで変わる。Search 多用型ならツール代、推論中心ならモデル代を見る
