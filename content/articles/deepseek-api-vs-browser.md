## リード

DeepSeekはブラウザのチャットからも、APIからも使えます。「ブラウザで十分では？」と感じるなら、違いは**人間が操作するか、プログラムが自動で呼ぶか**にあります。この記事では、料金・データ管理・向き不向きを整理し、どちらを選ぶべきか判断できるようにします。

## 前提

- 想定読者: DeepSeekをブラウザで使い始めた開発者
- 必要な環境: 不要（概念理解が中心）
- 前提知識: HTTPリクエストの基礎

## 本文

### 決定的な違いは「自動化できるかどうか」

ブラウザ版は人間が1回ずつ入力して結果を読むツールです。一方APIは、プログラムからHTTPリクエストで呼び出し、応答をコードで受け取ります。

この違いが効いてくるのは次のような場面です。

- 定型処理を毎日決まった時刻に実行したい
- 自分のアプリやCIに組み込みたい
- 大量の入力を一括で処理したい

ブラウザでは1件ずつ手作業になる処理が、APIなら自動化できます。**「ブラウザでできることを楽にする」のではなく「ブラウザではできないことを可能にする」**のがAPIです。

なお、ブラウザ版が内部的にどのような仕組みで動いているかは公開されていないため、本記事では推測で断定しません。

### 料金体系が根本的に違う

ブラウザ版は無料枠やサブスクリプション、APIは**トークン数に応じた従量課金**という形で提供されるのが一般的です。

| 観点 | ブラウザ版 | API |
|---|---|---|
| 課金の考え方 | 定額/無料枠 | 従量課金 |
| コストの予測 | しやすい | 利用量に依存 |
| 少量利用 | 向く | オーバースペックな場合がある |

具体的な単価・無料枠の条件は変更されることが多いため、**必ず公式ドキュメントで最新情報を確認してください**。本記事では変動しやすい数値は扱いません。

### データ・プライバシーの扱いが異なる

ブラウザ版とAPIでは、入力内容の取り扱いが規約で別に定められている場合があります。とくに業務利用では、

- 入力データが学習に使われるか
- 保存期間はどうなっているか
- リージョンやデータの所在

を確認する必要があります。これは推測で語れる話ではないので、**利用前に必ず各サービスの利用規約とプライバシーポリシーを確認してください**。

### 機能の向き・不向き

| 観点 | ブラウザ版 | API |
|---|---|---|
| 操作する主体 | 人間 | プログラム |
| 自動化 | 不可 | 可能 |
| アプリへの組み込み | 不可 | 可能 |
| 試用・調査 | 向く | やや手間 |
| プロダクト組込み | 不向き | 向く |

### どちらを選ぶか

判断はシンプルです。

- **試す・検討する・たまに使う** → ブラウザ版
- **サービスに組み込む・自動化する・大量処理する** → API

迷ったら「これを毎回手でやるか？」と自問してください。手作業でよいならブラウザ、自動化したいならAPIです。

## つまずきポイント

| 症状 | 対処 |
|---|---|
| APIキーの発行場所が分からない | プラットフォームのダッシュボードで発行。キーは`.env`などで管理し、コードに直書きしない |
| ブラウザとAPIで応答が違う | モデル・パラメータ・システムプロンプトの差を確認する |
| 料金が読めない | 利用量（トークン数）の見積もり方を学ぶ。詳細はシリーズ「コスト・性能」を参照 |
| 何から始めればよいか分からない | まずAPIキーを発行し、最小のリクエストを1つ送ってみる |

## まとめ

- 違いの本質は「人間が操作するか、プログラムが自動化するか」
- 料金はブラウザ版が定額系、APIが従量課金という根本的な差がある
- プロダクトへの組み込みや自動化をしたいならAPIを選ぶ
- データの扱いは規約で異なるため、業務利用前に必ず確認する
