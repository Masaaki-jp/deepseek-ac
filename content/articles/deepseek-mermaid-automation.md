## リード

記事からスライドを生成するパイプラインに Mermaid 図解を組み込むと、箇条書きだけでは伝わらない依存関係やアーキテクチャを1枚で示せます。ただし LLM の出力はしばしば崩れます。この記事では、**崩れを減らす事前判定**と、**崩れても致命的にしないフォールバック**の両方を、実際のコードとともに整理します。

## 前提

- 想定読者: LLM でスライド／動画素材を自動生成しているエンジニア
- 必要な環境: Python 3.10+、Pillow、Mermaid を画像化できる経路（API またはローカル）
- 前提知識: Markdown、Mermaid の基本構文、PPTX への画像貼り付け

## 本文

### まず「描かない」を決める

図解の破綻対策で最も効くのは、生成後の補正ではなく**生成させないこと**です。次のいずれかに当てはまるときだけ図を要求します。

- 4つ以上の要素と、その間の関係がある
- 時間の順序（前後・状態遷移）がある
- 包含関係や範囲の比較がある

逆に、答えが1文で済む場合、1つの関数の中身、数値を1つ聞かれているだけの場合は描かせません。箇条書きのほうが速く読めるためです。

### レンダリング経路の選択

Mermaid の画像化経路は複数あり、それぞれ弱点が違います。

| 経路 | 長所 | 弱点 |
|---|---|---|
| mermaid.ink (API) | 導入が最も簡単 | 外部サービス依存。503 や仕様変更に当たる |
| Kroki (API) | 図種別が多く安定 | GET のエンコードが特殊でハマりやすい |
| ローカルレンダラ | ネットワーク不要 | 日本語フォント解決に失敗すると豆腐（□）になる |

どれを選ぶにせよ、**失敗を前提にリトライとフォールバックを必ず組む**のが結論です。外部サービスの可用性・URL仕様は変わりうるため、採用時は公式ドキュメントで要確認してください。

### 矢印は曲線（basis）にする

Mermaid の flowchart は既定だと直交線で描かれ、ノードが多い図で線の交差が読みにくくなります。曲線に変えると交差の区別がつきやすくなります。設定はソース内の init ディレクティブで渡せます。

```mermaid
%%{init: {"theme": "dark", "themeVariables": {"background": "#1A1B26"}, "flowchart": {"curve": "basis"}}}%%
flowchart LR
  A[抽出] --> B[図解生成]
  B --> C[PPTX 合成]
```

API に渡す場合も、この init 行を含めたソース全体をエンコードすれば同じ設定が効きます。

### 破綻対策1: プロンプトでノード数を絞る

抽出プロンプトに次の制約を入れます。複雑な構成を1枚に詰め込ませず、階層化・抽象化させることが目的です。

```text
diagram フィールドには Mermaid flowchart を1つだけ書く。
制約:
- ノードは最大5個
- 必ず分岐（ツリー）を1つ以上含める
- ラベルは日本語20文字以内
- 出力は flowchart のコードブロックのみ。前置き・後書き禁止
```

### 破綻対策2: アスペクト比で貼り付けをスキップする

それでも極端に縦長・横長の図は生成されます。スライドに貼ると文字が読めないため、比率で弾いて箇条書きレイアウトに差し替えます。

```python
from PIL import Image

def aspect_ok(img: Image.Image, limit: float = 2.4) -> bool:
    w, h = img.size
    ratio = w / h
    return (1 / limit) <= ratio <= limit
```

スキップしたスライドでは、元の箇条書きを画面中央に大きく置くフォールバックに切り替えます。「読めない図」を映さないことが最優先です。

### ダークテーマへの適応（白背景の透過と線の反転）

API が返す画像は白背景・黒線です。そのまま貼ると白い四角が浮きます。Pillow で輝度をアルファに変換し、線だけを白にします。

```python
from PIL import Image

def to_dark(img: Image.Image) -> Image.Image:
    img = img.convert("RGBA")
    px = img.load()
    w, h = img.size
    for y in range(h):
        for x in range(w):
            r, g, b, _ = px[x, y]
            lum = (r * 299 + g * 587 + b * 114) // 1000
            px[x, y] = (255, 255, 255, 255 - lum)  # 白背景→透明、黒線→白
    return img
```

画素数が多い画像では遅いので、実運用では NumPy でベクトル化するか、縮小してから変換してください。

### 事実シートで図を検証する

LLM 生成の図は、抽出結果にないノードや辺を混ぜることがあります。`diagram` と並べて事実シートを持たせ、機械照合します（mizchi/explainer の `figures/<name>.facts.json` + `figure-check.mjs` の考え方を参考）。

```json
{
  "nodes": ["抽出", "図解生成", "PPTX 合成"],
  "edges": [["抽出", "図解生成"], ["図解生成", "PPTX 合成"]],
  "max_nodes": 5
}
```

Mermaid ソースをパースしてノード集合と辺集合を取り出し、事実シートと差分があれば**図を捨てて箇条書きに戻す**。これが最後の防波堤になります。

## つまずきポイント

| 症状 | 対処 |
|---|---|
| 図の文字が読めないほど小さい | アスペクト比 2.4 を超えたら貼り付けをスキップし、箇条書きにフォールバック |
| 日本語が豆腐（□）になる | ローカルレンダラのフォント指定を確認。API 経由ならフォント同梱可否を確認 |
| 図が白い四角として浮く | Pillow で白背景を透過し、暗い画素を白に反転 |
| 画像 API が 503 を返す | 指数バックオフでリトライ。最終失敗時は図なしレイアウト |
| ノードが増えて線が交差する | プロンプトで最大5ノード・分岐必須を強制。それでも崩れるなら2枚に分割 |
| 図に存在しない要素が混ざる | 事実シートと照合し、差分があれば図を破棄 |
| 字幕と図が重なる | 図の領域と字幕領域を上下で完全分離し、図の最大高さを固定 |

## まとめ

- 破綻対策で最も効くのは、生成前に「描かない」を判断すること
- ノード数制限（最大5個・分岐必須）とアスペクト比スキップの2段構えで、読めない図を排除する
- 外部レンダリング API は失敗前提でリトライとフォールバックを組む
- ダークテーマは Pillow で白背景透過＋線の反転を行えば溶け込む
- 事実シートとの照合を最後の防波堤にすると、幻の要素がスライドに残らない
