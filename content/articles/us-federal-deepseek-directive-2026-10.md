## リード

2026年10月19日、米国土安全保障省（DHS）が連邦文民機関に対し、DeepSeek製品の除去と使用禁止を指示した。DeepSeekモデルを組み込んだ第三者サービスも対象で、米政府向けに納品する請負業者にも波及する。本記事では、報道ベースで確認できる対象範囲と、開発現場でまず手を付けるべき点を整理する。

## 前提

- 想定読者: 米政府機関・連邦請負業者向けのシステムにAI機能を組み込むエンジニア、および調達・コンプライアンス担当
- 必要な環境: 特になし（コード例はripgrepとPython 3.10以降）
- 前提知識: 連邦調達の基本構造、APIベースのLLM利用とセルフホストの違い

> 本記事は聯合ニュース、BBC中文、Rti中央廣播電台など各社報道を整理したもの。**一次情報は連邦官報（Federal Register）に掲載されたDHS通知とその添付文書**であり、実務判断の前に原文を必ず確認してほしい。

## 本文

### 何が起きたのか

DHSが公表した通知の要点は、報道ベースで次のとおり。

- 根拠法: サイバーセキュリティ法
- 対象: 連邦の**文民機関**（財務省、国務省、司法省などが例示されている）
- 措置1: ITシステム上からDeepSeek製品を除去し、使用を全面禁止
- 措置2: **DeepSeekのAIモデルを基盤とする第三者サービス**の導入も禁止
- 措置3: DeepSeekの米連邦政府契約への参加を遮断
- 措置4: 政府ウェブサイトのトラフィック監視を各機関に指示
- 対象外: 軍事・情報機関。DHSは文民機関には指示できるが、国防総省などには及ばない

時系列で注意すべき点が2つある。

1つ目は、**公表は10月19日だが、BBCは「禁令は7月末から効力を生じている」と報じている**こと。公表日を「規制の起点」と読むと、社内の影響調査の対象期間を誤る。

2つ目は、中国側が「科学技術・経済貿易問題の政治化に反対」と反発していること。規制が今後、対抗措置や追加措置に発展する可能性は排除できない。

### DHSが挙げたリスク

通知の添付文書で示された論拠は、技術的な脆弱性というより**データの所在と法制度**に重心がある。

| 論点 | 内容 |
|---|---|
| サーバ所在地 | DeepSeekのサーバは中国に所在 |
| 法制度 | 中国法は政府に対し、民間企業のインフラへアクセスする「広範な権限」を与えている |
| データ移転 | 政府職員・請負業者が利用すると機密データが中国に渡る恐れ |
| 情報生産 | 米国民・機関に関する「実行可能な情報」を生成しうる |
| マルウェア | 悪意あるコードやその他の脆弱性を含む可能性 |

「モデル性能の話」ではなく「データ主権の話」である点が重要だ。したがって、モデルを自前ホストすればリスクが消えるのか、という論点は通知の外側に残る（後述）。

### エンジニアにとっての実務影響

規制の文面を読むより先に、自組織の依存関係を可視化したほうが早い。やることは3つ。

**1. コード内のDeepSeek依存を洗い出す**

```bash
# リポジトリ内のDeepSeek API参照・モデル名を検出
rg -n --hidden -i \
  -e 'api\.deepseek\.com' \
  -e 'deepseek[-_/](chat|reasoner|coder|v3|r1)' \
  --glob '!node_modules' --glob '!.git' --glob '!*.lock'
```

設定ファイル、IaC、CIのシークレット名、プロンプト定義（YAML/JSON）まで含めて検索するのがコツ。モデル名は設定ファイル側にだけ書かれていることが多く、コードだけ見ると見落とす。

**2. 呼び出しをプロバイダ抽象の裏に寄せる**

規制対応は「今すぐ消す」より「ポリシーで切り替えられる形にする」ほうが継続運用に強い。

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Policy:
    blocked_providers: frozenset[str]
    blocked_model_prefixes: tuple[str, ...]

# 調達先ごとに切り替える（連邦文民機関向けは厳格側を適用）
STRICT = Policy(
    blocked_providers=frozenset({"deepseek"}),
    blocked_model_prefixes=("deepseek-", "deepseek/"),
)

def assert_provider_allowed(provider: str, model: str, policy: Policy) -> None:
    if provider in policy.blocked_providers:
        raise PermissionError(f"provider '{provider}' is blocked by policy")
    if model.startswith(policy.blocked_model_prefixes):
        raise PermissionError(f"model '{model}' is blocked by policy")
```

この手のポリシーチェックは**リクエスト時**に置く。設定読み込み時だけだと、環境変数やフォールバック経路からすり抜ける。

**3. データの流れを棚卸しする**

API呼び出しを消しても、以下に残る。

- 埋め込みベクトル（生成元がDeepSeekなら、それ自体が派生物）
- プロンプト・レスポンスのログ、APM、エラートラッキング
- 社内SaaSが内部でDeepSeekを使っているケース（「DeepSeekモデルを基盤とする第三者サービス」の禁止が効く部分）
- 開発者個人のアカウントによる利用（シャドーAI）

### 波及が及ぶ範囲

**連邦請負業者**: 元請け契約を通じてフローバック条項で要求が降りてくる可能性が高い。自社が直接APIを叩いていなくても、再委託先の利用実態を説明できる状態にしておきたい。

**日本企業・非政府機関**: 米政府の直接の管轄外だが、次の2経路で影響が来る。

1. 米政府向け納品物にAI機能が含まれる場合（サプライチェーン経由）
2. 調達契約に「AIモデルの提供元開示」条項が入る場合

後者は規制そのものより**契約実務の変化**として効いてくる。提供元・ホスティング先・再学習の有無を記載した「AI-BOM（部品表）」的な資料を用意しておくと、今後の調達回答が速くなる。

### 現時点で確定していない点

報道からは読み切れない論点が残っている。**推測で実装方針を決めず、原文と各機関のCIOガイダンスで確認すべき**。

- オープンウェイトを自組織内で完全セルフホストする場合の扱い（通知は「製品」と「DeepSeekモデルを基盤とする第三者サービス」に言及）
- 「第三者サービス」の範囲（ファインチューニング済みモデル、蒸留モデル、Ollama等での再配布を含むか）
- 施行日と遡及範囲、違反時の具体的な措置
- 軍事・情報機関が独自基準で別途措置を設けるか

## つまずきポイント

| 症状 | 対処 |
|---|---|
| 「OSSだから規制対象外」と判断してしまう | 提供形態（ホスト型かセルフホストか）とモデルの系譜で判断する。原文の定義を確認 |
| APIキーを消して完了とした | 埋め込み、ログ、APM、社内SaaSの内部利用まで確認する |
| 「国防総省は対象外だから全社OK」と結論 | 文民機関向け納品は別基準。契約単位で切り分ける |
| 公表日（10/19）を起点に影響調査 | BBC報道では7月末から効力。調査対象期間を広げる |
| 規制対応で可用性が落ちる | プロバイダ抽象化＋ポリシー切替で、機能を止めずに差し替えられる形にする |

## まとめ

- DHSは2026年10月19日、連邦文民機関にDeepSeek製品の除去・使用禁止と、DeepSeekモデル由来の第三者サービスの導入禁止を指示した
- 論拠はモデル性能ではなく、サーバ所在国と法制度に起因するデータ主権リスク
- 実務は「コード検索 → プロバイダ抽象化 → データフロー棚卸し」の順で進めるのが速い
- セルフホストの扱いなど未確定部分は多く、一次情報（連邦官報の通知原文）の確認が前提
- 米政府に直接納品しない企業も、サプライチェーンと調達条項の2経路で影響を受ける
