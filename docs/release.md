# 公開前に残る作業

## 必要情報

- 正式な開発フォルダ・Gitホスティング先とリポジトリ
- Cloudflareアカウント、既存プロジェクト、deepseek.acのDNS管理先
- note記事、YouTube動画、2冊のAmazon URL、許諾のある表紙素材
- 公開プロフィール・制作実績・問い合わせ先
- 本文・画像・コードの再利用条件

## 公開設定案（未実行）

Cloudflare Pagesで承認されたGitリポジトリを接続。本番ブランチmain、ビルド`pnpm build`、出力`dist`。Nodeバージョンとpnpmはロックファイルに合わせる。Git側で作業ブランチ→チェック→レビュー→mainへの反映を運用する。ブランチ保護の利用可否・料金は選択するアカウントで確認。

公開操作の前に、ユーザーへプロジェクト名・リポジトリ・ブランチ・ドメイン・公開内容を提示して確認を得る。契約・DNS変更・Git push・公開はまだ行っていない。

Cloudflare上では成功ビルドだけを公開し、失敗した試験ビルドで旧版が残ることを確認。独自ドメインをPages側で関連付けてから、既存DNSレコードとの競合を確認して変更する。変更前のDNS値を記録する。

## 公開判定

- 準備中の表記・書籍・問い合わせ先を実情報に置き換える
- 教材を検証し、費用・日付・出典・権利・書籍対応を記入
- 依存パッケージの脆弱性監査とサポート確認
- 利用条件、配信事業者のプライバシー情報を確定
- noindex/robotsを公開用に更新
- PC/タブレット/スマートフォン、200%文字拡大、キーボード操作を最終確認
- CMSで新規作成・保存・編集・プレビュー・公開対象指定を通しで確認
- Git差分・ビルド・全内部リンク・画像代替文・Markdown一致を確認
- HTTPS、独自ドメイン、404、失敗ビルド時の旧版維持、ロールバックを確認

APIやGCPで費用が生じる実行は目的と費用目安を説明して確認を得てから行う。
